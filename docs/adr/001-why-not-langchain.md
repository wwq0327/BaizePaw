# ADR-001: 为什么不直接用 LangChain

## 状态
已通过

## 背景
搭建 BaizePaw 时面临技术选型：是用 LangChain 这样的成熟框架，还是自己从 0 实现？

## 决策
自己从 0 实现，不用 LangChain。

## 原因

### 1. 学习目的
用户想"从 0 开始理解 Agent 是怎么工作的"。LangChain 太黑盒了，出了问题不好排查。

### 2. 简单性
LangChain 封装了很多东西，但也引入了很多概念。学习曲线陡峭，而且限制了你对底层机制的理解。

### 3. 可控性
自己写的代码，每一步都能 print 出来看。出了问题立刻知道在哪。

### 4. 够用就好
当前的需求很简单：多轮对话 + 几个工具调用。不需要 LangChain 的复杂编排能力。

## 代价

- 需要自己处理很多边缘情况
- 可能没有 LangChain 那么"健壮"
- 需要自己跟进 API 变化

## 结果

**正面：**
- 代码简单易懂
- 问题定位快速
- 学习曲线平缓

**负面：**
- 一些边界情况需要自己处理
- 没有 LangChain 的生态（丰富的工具集成）
