## 阶段一：项目初始化

### 目标
从零开始搭建 BaizePaw 项目结构。

### 做法
- 使用 Python 3.x，共用 `my/.venv` 虚拟环境
- 项目结构：

```
BaizePaw/
├── src/
│   ├── agent.py           # AgentRunner
│   ├── llm_client.py     # LLM 调用
│   ├── chat_history.py    # 对话历史
│   └── tools/
│       ├── dispatcher.py  # 工具调度
│       ├── calculator.py  # 计算器
│       ├── search.py      # 搜索
│       └── file_ops.py   # 文件读写
├── config.py              # API 配置
├── main.py                # 入口
└── requirements.txt
```

### 关键决策
- **为什么不直接用 LangChain？** 我们想从原理上理解 Agent 是怎么工作的，LangChain 太黑盒了
- **工具调用格式**：自己发明了一个简单的标记格式 `【tool】xxx【/tool】`

## 阶段二：API 接入

### 目标
让 Agent 能调用 LLM 并获得回复。

### 做法
- 对接 DeepSeek API（`https://api.deepseek.com/v1`）
- Model：`deepseek-v4-flash`
- 使用 `requests` 库发送 HTTP 请求

### 遇到的问题

**问题 1：API Key 找不到**

环境变量 `DEEPSEEK_API_KEY` 在新 session 中无法读取。

**原因**：`~/.zshrc` 中定义的环境变量需要 `source ~/.zshrc` 才能加载。

**解决**：在运行前手动 `export DEEPSEEK_API_KEY="sk-xxx"`

## 阶段三：让 LLM 知道工具调用

### 目标
LLM 能识别我们的工具格式并触发调用。

### 遇到的问题

**问题：LLM 按普通对话回复，不触发工具**

LLM 返回：
```
抱歉，我无法直接读取你电脑上的文件...
```

**原因**：LLM 不知道 `【tool】xxx【/tool】` 这个格式是我们发明的，它以为用户在问它解释这个格式。

**解决**：添加 System Prompt，告诉 LLM：

```
你叫白泽（BaizePaw），是一个个人助手。

当你需要完成具体任务时，请使用以下工具格式：
- 计算：使用【tool】calculator【/tool】后跟表达式
- 读取文件：使用【tool】file_read【/tool】后跟文件路径

格式示例：
「帮我计算 2+2」→ 【tool】calculator【/tool】2+2
```

## 阶段四：工具调用流程

### 目标
让工具能被正确调用并返回结果。

### 遇到的问题

**问题 1：400 Bad Request — tool_call_id 缺失**

```
Messages with role 'tool' must be a response to a preceding message with 'tool_calls'
```

**原因**：DeepSeek API 要求 tool message 必须对应一个 `tool_calls` 字段，但我们只是简单地把工具结果作为 message 发回去。

**分析**：这是 OpenAI/DeepSeek 的 function calling 规范。我们用的"自发明格式"不兼容这个规范。

**解决**：换一种方式 — 不发 tool result 作为 message，而是：
1. 解析到工具调用后，执行工具
2. 直接把结果返回给用户
3. 下一轮对话时让 LLM 继续

```python
# 第一次工具调用：直接返回结果
if i == 0:
    return f"【{tool_name}】执行结果：{tool_result}"

# 后续工具调用：让 LLM 继续处理
result_message = f"工具「{tool_name}」执行结果：{tool_result}"
self.history.add_user(result_message)
```

**问题 2：参数传递错误**

```
Tool error: read_file_tool() got an unexpected keyword argument 'expr'
```

**原因**：Agent 把所有参数都塞进 `{"expr": ...}`，但 `file_read` 需要 `{"path": ...}`

**解决**：根据工具类型映射参数：

```python
if tool_name == "calculator":
    params = {"expr": tool_params}
elif tool_name in ("file_read", "search"):
    params = {"path": tool_params}
elif tool_name == "file_write":
    params = {"path": path, "content": content}
```
