# v0.3 角色系统与细节打磨

> 日期：2026-05-03
> 目标：给 Agent 定义清晰的角色定位和行为准则，补齐细节

---

## 背景

v0.2 架构重设计完成后，Agent 能跑，但 system prompt 只有一句：

```
你叫白泽（BaizePaw），是一个个人助手。
```

这个"个人助手"太模糊了。LLM 不知道自己是干什么的，不知道边界在哪，也不知道是什么沟通风格。

角色定义决定了 Agent 的行为质量。没有清晰定义，LLM 会自由发挥——可能话太多、可能不该做的事情做了、可能凭空编造结果。

---

## 设计过程

### 讨论

和 Claude 讨论了角色系统的几个方向：

1. 工具型 — 纯粹执行命令，不多话
2. 伙伴型 — 有个性，像 Jarvis
3. 两者之间 — 高效简洁但带点温度

选了 3，从最简单的入手：效率工具定位。

### 四个维度

角色定义最终确定四个维度：

1. **做什么（使命）** — 一句话说清存在意义
2. **能做什么（能力）** — 如实描述现有工具能做的事
3. **不能做什么（约束）** — 硬边界，这是最重要的部分
4. **沟通风格** — 简洁、上下文感知、出错解释

### 关键认知

讨论过程中发现了一个重要原则：**角色定义要和代码分离**。

- 角色定义放在独立文件 `AGENT.md` 中
- `src/role.py` 提供一个 `load_role()` 函数，读取文件内容
- `ToolDispatcher.generate_system_prompt()` 接受 `role_prompt` 参数注入
- `Core.__init__()` 加载角色并传给 dispatcher

这样做的好处：改角色行为不需要改代码，编辑 AGENT.md 即可。以后可以加多个角色文件切换。

## 实现

### Task 1: 角色文件

`AGENT.md` 放在项目根目录，可见性最高：

```markdown
# 白泽（BaizePaw）

你叫白泽，是一个本地效率助手。

## 1. 做什么（使命）
帮助用户管理本地文件和完成日常任务。

## 2. 能做什么（能力边界）
...

## 3. 不能做什么（硬约束）
- 安全边界 — 绝不操作 cwd 之外的文件
- 明确授权 — 只操作用户明确指定的路径
- 诚实报告 — 工具返回什么就是什么
- 不假装执行 — 只有工具确实返回结果后才报告
- 不越界 — 用户没要求的事不做

## 4. 沟通风格
- 简洁优先 — 直接给结果，不寒暄
- 上下文感知 — 文件路径默认用相对路径
- 出错时解释 — 简短说明原因和建议
```

### Task 2: 加载机制

`src/role.py` 只有 8 行：

```python
def load_role(path: str = None) -> str:
    if path is None:
        path = os.path.join(
            os.path.dirname(os.path.dirname(os.path.abspath(__file__))),
            "AGENT.md",
        )
    with open(path, "r", encoding="utf-8") as f:
        return f.read().strip()
```

默认从项目根目录读 AGENT.md，也支持传自定义路径。

### Task 3: 注入到 system prompt

`ToolDispatcher.generate_system_prompt(role_prompt=None)` 新增参数。不传时自动调用 `load_role()`。角色文本放在 system prompt 最前面，作为 AI 的"身份卡"。

## 同时修复的问题

### reasoning_content 丢失导致 400

DeepSeek thinking mode 会在响应中包含 `reasoning_content` 字段，必须在后续请求中原样传回。

**现象**：TUI 发送第二条消息时报 400 —— `The reasoning_content in the thinking mode must be passed back to the API.`

**修复**：
- `LLMClient.chat()` 返回 `ChatResponse` 对象，包含 `content` 和 `reasoning_content`（`__str__` 返回 content 保证向后兼容）
- `AssistantMessage` 新增 `reasoning_content` 可选字段
- `to_dict()` 条件包含 `reasoning_content`
- `Core.run_iter()` 提取并传回

### TUI 文本不能选中复制

Textual 8.2 的 RichLog 不支持文本选择。解决方案：绑定 `y` 键，按 y 时用 `pbcopy`（macOS）将最后一条 DoneEvent 的内容复制到系统剪贴板。状态栏显示 "Copied!" 反馈。

### TUI 长文本不换行

RichLog 默认水平滚动。加 `wrap=True` 启用自动换行，CSS 加 `overflow-x: hidden` 禁用水平滚动条。

## 踩坑

- **RichLog 没有 selectable 参数**：Textual 8.2 的 RichLog 不支持这个参数，直接传会 TypeError。最终用 y 键复制方案替代。
- **reasoning_content 是 DeepSeek 特有的**：OpenAI 兼容接口没有这个字段，但 DeepSeek 思考模式会返回。这个坑花了一些时间定位。
